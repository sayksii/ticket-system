## 不 push 也能先看 UI

在專案根目錄執行：

```powershell
node scripts/preview-frontend.mjs
```

打開 http://127.0.0.1:4173 。這個預覽讀取目前尚未提交的前端檔案，
/api 轉發到 K3s 的 10.10.10.10，Host 使用 ticket.local。
所以要先啟動 K3s、Harbor，並確定後端、MySQL、Redis、RocketMQ、Order Worker 正常。
預覽只綁定本機，不公開到區域網路。終端機按 Ctrl+C 可關閉。

如果只想看成功藥丸的配色，不想真的搶票，可在網址加上 `?previewToast=success`。
這是本機工具提供的「樣式預覽」，通知會明確標示，不建立訂單、不消耗票數。正式部署沒有這個預覽功能；正常頁面仍只在後端確認 SUCCESS 後顯示成功通知。

## 為什麼本機預覽能讀到後端資料？會不會跨域？

目前活動與訂單查詢走這條路：

```text
瀏覽器 → 本機預覽伺服器 :4173 → K3s Ingress → Spring Boot → MySQL
```

前端使用 `/api/events`、`/api/orders` 這類相對網址。當網頁在
`http://127.0.0.1:4173`，瀏覽器請求的 API 也是同一個協定、主機與埠號，所以是同源。
本機的 scripts/preview-frontend.mjs 收到 `/api` 後，才代為轉發到 `10.10.10.10`，
並帶上 `Host: ticket.local`，讓 Ingress 導向 ticket-backend:8080。
跨來源限制是瀏覽器的限制，不是這段伺服器轉發、或後端 JDBC 連 MySQL 的限制。
前端不直接連資料庫，瀏覽器也不需要資料庫帳密。

部署到 ticket.local 時也一樣：`/` 由 Ingress 送到前端，`/api` 送到後端，
瀏覽器看到的都是 ticket.local，不因為前後端位在不同 Pod 而變成跨域。

如果改成讓瀏覽器直接請求另一個主機或埠號，才需要 CORS 放行。
目前 backend 的 WebConfig 對 `/api/**` 有 `allowedOrigins("*")`，允許 GET／POST 的跨來源存取；
但現在的同源代理路徑不依賴它。正式上線時應評估縮限允許來源、補上身分驗證；
CORS 本身不是登入驗證。這次只確認設定，沒有修改它。

注意：這不是假資料頁。按「立即搶票」會建立真實的示範訂單、消耗一張測試票。
建議在右上角切換成 portfolio-demo 等展示用 ID，避免影響原本的測試帳號。

## 已有資料庫，怎麼安全增加活動

backend/src/main/resources/data.sql 和 k8s/part7/10-mysql.yaml 已包含六場活動：

| 活動 | 新建時的總票數 |
| --- | ---: |
| Kubernetes DevOps Concert | 20 |
| Cloud Native Summit | 120 |
| Spring Boot Workshop | 80 |
| Indie Music Night | 60 |
| Future Design Expo | 100 |
| Weekend Jazz Market | 40 |

這些 SQL 只新增還不存在的名稱，不修改既有活動的票數。
MySQL 的初始化 ConfigMap 只在空資料卷第一次啟動時生效；
修改 YAML 不會自動把新活動加進已使用的資料庫。

把最新專案放到 k3s-server，從專案根目錄執行：

```bash
bash scripts/seed-demo-events.sh
```

它做兩件事：

1. 把缺少的活動加入 MySQL，已有活動原封不動。
2. 新活動沒有訂單，且 Redis 的 stock / buyers / status 三個 key 全部不存在時，才初始化庫存與 OPEN 狀態。

重複執行會跳過已存在的資料。沒有 DELETE、TRUNCATE、FLUSH 或重置 buyers。
如果活動已經有訂單，但 Redis 狀態缺少，這支腳本不會擅自補庫存；
請先排查，不要為了讓按鈕能按就盲目重置。
不要用 part7-reset.sh 來新增活動，它會清除資料。

## 如何拍一張完整的成果圖

桌面寬螢幕顯示六張卡片。先用展示 ID 搶票，確定訂單成立；
再點右上角頭像展開訂單面板，在成功通知消失前截圖。
目前通知保留 14 秒。訂單列表是可捲動的小面板，不會把整頁推開。
不需要捏造訂單，或把「QUEUED」包裝成已成立。

先確認 harbor-log 已是 healthy，再啟動原有 Harbor 容器：

```bash
sudo docker compose -f /home/ubuntu/harbor/docker-compose.yml start
```

這個命令是在 harbor VM 執行，只啟動現有容器，不重建、不清空資料卷。
Harbor 正常後，K3s 會自動重試拉映像檔；因為拉取失敗有退避時間，
恢復不一定是立刻。不要為了催它恢復就刪除 PVC 或重置資料庫。
